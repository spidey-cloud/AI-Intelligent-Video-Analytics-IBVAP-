 EXECUTIVE SUMMARY 
 
Border security forces currently deploy extensive CCTV infrastructure across Border Out 
Posts (BOPs), check posts, and strategic locations. However, these systems are limited to 
passive recording and require continuous human monitoring, leading to missed security 
incidents, operator fatigue, and delayed responses. 
 
Our solution, IBVAP (Intelligent Border Video Analytics Platform), transforms existing 
CCTV infrastructure into an intelligent, AI-powered surveillance network through a 
centralized, zero-hardware-cost software platform. The system requires no additional 
hardware at BOPs, no camera replacement, and minimal infrastructure investment—
leveraging existing networks and servers already deployed by SSB. 
 
Total deployment cost: ₹2-5 lakhs for unlimited cameras (software development + central 
server optimization only).

 5. HOW WE ACHIEVE MINIMAL COST 
 
 5.1 Technical Optimizations 
 
 A) CPU-Only Processing (No Expensive GPUs) 
Problem: GPUs cost ₹50,000-₹3,00,000   
Solution: 
- Use highly optimized CPU inference (ONNX Runtime, INT8 quantization) 
- Process at 3-5 FPS per camera (sufficient for security; humans react slower anyway) 
- Lightweight models (YOLOv8-nano: 6MB, runs real-time on CPU) 
 
Result: 1 CPU server handles 50-100 cameras (vs. needing GPUs) 
 
 B) Selective Processing (Process Only When Needed) 
Problem: Processing all frames 24/7 wastes compute   
Solution: 
- Trigger analytics only when motion detected (most CCTV has basic motion) 
- Smart frame sampling (process every 2nd or 3rd frame) 
- Night-time: process only if IR camera shows activity 
 
Result: 60-80% reduction in compute load 
 
 C) Event-Only Storage (Not Continuous Recording) 
Problem: Storing 100 cameras × 24/7 = petabytes   
Solution: 
- Store only 10-20 sec clips around events (intrusion, alert) 
- Keep snapshots + metadata (timestamps, bboxes) 
- 100 cameras, ~50 events/day = ~100GB/month (vs. 100TB for continuous) 
 
Result: 99% reduction in storage cost 
 
 D) Adaptive Streaming (Bandwidth Optimization) 
Problem: Streaming 100 cameras at full resolution kills bandwidth   
Solution: 
- Stream at reduced resolution for analytics (640×360 sufficient for detection) 
- Only pull full-resolution on alert (for evidence) 
- Only pull frames when analytics running (not continuous) 
 
Result: 70-90% reduction in bandwidth usage 
===== PAGE 8 =====
 
 E) Containerized Architecture (Efficient Resource Use) 
Problem: Traditional VMS wastes resources   
Solution: 
- Docker containers share CPU/RAM dynamically 
- Kubernetes auto-scales based on load 
- No idle resource waste 
 
Result: 40-60% better resource utilization
